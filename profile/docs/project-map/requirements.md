# 프로젝트 지도 PRD

## 1. 배경과 문제

프로필 방문자는 공개 작업이 무엇인지 빠르게 파악하기 어렵고, 비공개 작업은 존재 여부와 관계없이 이름·설명·링크가 노출되어서는 안 된다. 프로필 안에서 공개 작업과 보호된 작업을 구분하는 간결한 지도가 필요하다.

## 2. 대상 사용자

- 프로필을 처음 방문해 작업 범위를 빠르게 파악하려는 사람
- 공개 저장소와 비공개 작업의 경계를 확인하려는 협업자
- 프로필을 유지하는 계정 소유자

## 3. 핵심 가치와 성공 신호

- 공개 저장소의 구조를 한 화면에서 읽을 수 있다.
- 비공개 저장소의 원본 이름, URL, 설명, 언어, 수정 시각이 프로필 산출물에 남지 않는다.
- 저장소 정보가 바뀐 뒤 정기 실행 또는 수동 실행으로 지도 자산이 갱신된다.

## 4. 범위(포함)

- `PROJECT MAP` SVG 생성
- 10개 언어 README의 접기·펼치기 프로젝트 지도 섹션
- 공개 저장소 자동 조회와 캐시 버전 갱신
- 선택적 읽기 전용 시크릿을 통한 비공개 저장소 개수의 안전한 마스킹
- GitHub Actions 정기·수동 실행과 변경 시에만 생성 파일 커밋
- 생성기 단위 검증과 원격 워크플로 QA

## 5. 비목표(제외)

- 비공개 저장소 이름, URL, 설명, 언어, 이슈, 커밋 정보 노출
- 실시간 웹훅 기반 갱신
- GitHub README에서 지원하지 않는 JavaScript 기반 대화형 UI
- 외부 유료 호스팅이나 별도 배포 서비스

## 6. 사용자 시나리오

1. 방문자가 프로필의 `프로젝트 지도 보기`를 연다.
2. 공개 프로젝트와 보호된 비공개 작업 영역을 시각적으로 구분해 본다.
3. 공개 저장소가 궁금하면 명시적인 저장소 목록 링크를 연다.
4. 계정 소유자는 수동 실행 또는 정기 실행으로 최신 지도를 갱신한다.

## 7. 요구사항 목록

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| REQ-01 | 공개 프로젝트와 보호된 비공개 작업을 분리한 SVG 지도를 생성한다. | P0 | `profile/assets/maps/project-map.svg`가 생성되고 공개 프로젝트와 보호 영역을 표시한다. |
| REQ-02 | 비공개 원본 메타데이터를 지속 산출물에 저장하지 않는다. | P0 | SVG, JSON, README, 로그, 커밋 메시지에서 원본 비공개 이름이 발견되지 않는다. |
| REQ-03 | 모든 언어 README에서 접기·펼치기 방식으로 지도를 제공한다. | P0 | 10개 README에 프로젝트 지도 `<details>`가 있고 로컬 SVG 링크가 유효하다. |
| REQ-04 | 프로젝트 상태의 의미 있는 변화가 있을 때만 생성 파일과 캐시 버전을 갱신한다. | P0 | 같은 입력으로 두 번 실행해도 두 번째 실행에서 diff가 없다. |
| REQ-05 | 수동 실행과 정기 실행이 가능하고, 변경 시에만 생성 결과를 커밋한다. | P0 | 워크플로에 `workflow_dispatch`, `schedule`, 명시적 생성 파일 스테이징이 있다. |
| REQ-06 | 읽기 전용 시크릿이 있을 때만 비공개 저장소 개수를 반영한다. | P1 | 시크릿 미설정 시에도 워크플로가 성공하며, 설정 시 마스킹된 개수만 반영한다. |
| REQ-07 | 외부 API의 일시 오류가 발생해도 제한된 시간 안에 재시도하거나 실패한다. | P1 | 408, 429, rate-limit 403, 502, 503, 504, 네트워크 오류는 최대 3회 시도하고, 그 외 4xx는 즉시 실패하며 기존 원격 자산은 유지된다. |
| REQ-08 | 포크와 보관된 저장소를 공개 프로젝트 카드에 포함하지 않는다. | P1 | 동일 계정의 활성 비포크 공개 저장소만 지도 상태와 SVG에 나타난다. |

## 8. 제약과 가정

- GitHub README는 네이티브 `<details>`와 정적 SVG만 안정적으로 제공한다.
- 기본 `GITHUB_TOKEN`은 프로필 저장소 밖의 비공개 저장소를 읽는 용도로 가정하지 않는다.
- 선택적 `PROFILE_REPOSITORY_READ_TOKEN`은 선택한 비공개 저장소에 대한 읽기 전용 권한만 가져야 한다.
- GitHub Actions 사용량은 계정의 포함 한도와 정책을 따른다. 외부 유료 서비스는 사용하지 않는다.

## 9. 미확정 항목

- 비공개 저장소 자동 감지용 읽기 전용 시크릿 연결 여부: 계정 소유자 결정 필요.
- 첫 글자를 보이는 마스킹 모드: 기본값은 비노출이며, 노출이 필요하면 별도 동의가 필요하다.
